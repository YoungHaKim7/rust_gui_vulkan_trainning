# 파이썬 예시 실행할때 문제점 해결
- Fixed — `uv run animated_urdf.py` now works end-to-end (verified with `--save`: 10000-step, 5.2MB recording, and the viewer opens it via Vulkan). There were five stacked problems:

1. **Missing `rerun_py/pyo3-build.cfg`** — normally generated by pixi activation (`ensure-rerun-env`), which doesn't exist on this machine. Generated it with the repo's own logic in `rerun_pixi_env/src/rerun_pixi_env/pyo3_config.py`, pointed at the uv-managed CPython 3.11 that the workspace `.venv` uses.
2. **Missing `protoc`** — installed the official protoc 35.1 binary to `~/.local/bin` (no sudo needed).
3. **Missing native viewer binary** — the wheel build requires `rerun_py/rerun_sdk/rerun_cli/rerun`. Built it with the repo's no-web-viewer recipe (adapted to `--features base` since nasm isn't installed), and staged the binary like `py-build-wheel` does.
4. **Stale editable install** — `import rerun` failed because the workspace `.venv` was missing `rerun-dev-fixup` (the dev package that fixes sys.path for maturin editable installs and sets `RERUN_CLI_PATH`). Installed it with `uv pip install`.
5. **LFS pointers** — `so100.urdf` + 13 STLs were pointer stubs (git-lfs isn't installed). Fetched all 14 real files via GitHub's LFS batch API, sha256-verified.

Two notes:

- `git status` currently shows those 14 `.stl`/`.urdf` files as modified — that's just because the lfs clean-filter isn't installed to compare them; the content is byte-correct. Installing git-lfs properly (`sudo apt install git-lfs && git lfs install`) makes it show clean. Recommended since CLAUDE.md notes LFS is required for test snapshots anyway.
- I saved a memory of this machine's no-pixi setup checklist so future build failures here don't need re-diagnosis.
